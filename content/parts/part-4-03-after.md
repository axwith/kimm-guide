# 강의 뒤에 계속 쓰기

> 오늘은 최근 자료 10개 이내로 KB를 시작했습니다. 공고 적합도, 시나리오, 기획서는 모두 `70-kb` 를 먼저 읽습니다. KB가 쌓일수록 결과가 내 실적과 문체에 더 잘 맞습니다.
> 실습 폴더 안의 `KB-구축가이드.md` 에 같은 내용이 있습니다.

---

## 1. 넣기 전에 — 보안부터

- 소속 기관의 AI 사용 지침을 먼저 확인합니다. Claude Code가 읽은 파일은 처리를 위해 Anthropic 서버로 전송됩니다.
- 이미 공개한 자료(논문, 학회 발표, 공개 보고서)부터 넣습니다.
- 미공개 자료는 기관이 승인한 환경에서만 다룹니다. 프로필에는 `[비공개]` 로만 적습니다.

## 2. 넣는 순서 — 묶음으로

한 번에 10~20개씩 `00-inbox` 에 넣고 흡수합니다. 결과 표를 확인한 뒤 다음 묶음을 넣습니다.

```text
/kb ingest
```

| 우선순위 | 자료 | 쓰이는 곳 |
|---|---|---|
| 1 | 평가 결과·심사 의견 | 왜 됐고 왜 떨어졌는지. 가장 값진 자료 |
| 2 | 과거 계획서·결과보고서 | 실적 증빙, 문서 구성 |
| 3 | 논문·특허 | 실적 증빙, 방법·용어 |
| 4 | 장비·데이터 목록 | 보유 역량. 증빙이 있어야 "보유" |
| 5 | 발표 자료 | 문장·구성 습관 |

## 3. 넣은 뒤에 — 확인

```text
/kb 내 실적 중 ○○ 관련만 보여 줘
```

답에 원본 위치가 붙는지 봅니다. 비어 있는 칸은:

```text
/kb gaps
```

## 4. 유지

- 논문이 나오거나 과제가 끝날 때마다 바로 `00-inbox` 에 넣고 흡수합니다.
- 한 달에 한 번 점검합니다(중복, 낡은 정보, 증빙 없는 "보유").

```text
/kb check
```

## 5. 자동으로 돌리기

| 무엇 | 언제 |
|---|---|
| 세션 기록 원자료 | 세션이 끝날 때마다(훅, 할 일 없음) |
| 기록 정리 | 다음 세션 시작 때 |
| 하루 마감 `/wrap` | 매일 18:00(예약) |
| 주간 공고 `/weekly` | 매주 월 08:30(예약), 결과는 `50-grants\{날짜}-weekly.md` |

등록(한 번만, Claude Code CLI 설치·로그인 필요):

```powershell
powershell -ExecutionPolicy Bypass -File C:\work\kimm\research-planner\60-scripts\schedule_windows.ps1
```

예약 실행은 승인 창에 답할 사람이 없으므로 파일 편집, python 스크립트, 웹 조회만 허용해 둡니다. 결과는 다음 날 `logs\schedule-wrap.log`, `logs\schedule-weekly.log` 에서 확인합니다.
